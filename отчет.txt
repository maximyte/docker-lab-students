1. Если образа hello-world нет на компьютере, Docker автоматически скачивает его из Docker Hub, создаёт из него контейнер и запускает. После вывода приветственного сообщения контейнер завершается, потому что его программа закончила работу. Команда docker ps показывает только работающие контейнеры, а docker ps -a — все, включая завершённые.

2. После команды exit оболочка bash завершилась, поэтому контейнер Ubuntu остановился. Он остался в docker ps -a со статусом Exited (0), потому что эта команда показывает и остановленные контейнеры. В docker ps его нет, так как она показывает только работающие контейнеры. На моём компьютере установлена macOS 15.7.4, а внутри контейнера используется Ubuntu.

3. docker stop останавливает контейнер, но сохраняет его вместе с файлами и настройками. Он остаётся в docker ps -a, и его можно снова запустить через docker start.
docker rm удаляет контейнер и изменения файлов внутри него. После этого он исчезает из docker ps -a, и запустить его снова уже нельзя — нужно создать новый.

4. фром берет готовый образ
WORKDIR - рабочая папка
COPY - копируем файл в папку 
CMD - при запуске контейнера выполняем файл питона

5. После изменения текста в app.py и повторной сборки Docker использовал кэш для неизменившихся шагов. Шаг COPY выполнился заново, чтобы скопировать обновлённый файл. При запуске нового контейнера вывелось новое сообщение «пыпа».

7. Данные MySQL хранятся в томе mysql-data по пути /var/lib/docker/volumes/mysql-data/_data. На macOS этот путь находится внутри Linux-виртуальной машины Docker Desktop. В контейнер том подключён к папке /var/lib/mysql. Поэтому данные сохраняются после удаления контейнера.
